# Liquid Glass Interface Three-Mode Skill Decision Record

**Date:** 2026-08-13
**Status:** Implemented locally; not deployed or published

## 1. Scope and Decision

Synchronize（同步） the repository's single `liquid-glass-interface` Skill with the
current React implementations and keep three fixed, explicitly selectable modes
in one distributable（可分发） Skill:

- `v1-fidelity`: frozen, low-freedom V1 reproduction.
- `v2-default`: the default vertical navigation and Liquid Glass card route.
- `v3-horizontal`: the independent M04 horizontal navigation-lens route.

When no mode is named, select `v2-default` unless the request explicitly
triggers V1 or V3. An unknown `vN` must request a supported selection rather
than guessing. `/v3-05-failed` and `v3-milestone-05-failed` remain failed-M05
historical archives（历史归档） only: they are not Skill assets, modes, verifier
inputs, or visual-acceptance baselines.

## 5. Known Risks, Limits, and Follow-up

- Automation verifies portability and repository contracts, but not the human
  visual gate. V1 still requires explicit user high-fidelity approval after
  desktop and `<=560px` review; V2/V3 still require manual checks for themes,
  focus, keyboard use, lens refraction, narrow layouts, reduced motion, and
  forced colors.
- The asset verifiers intentionally fail when their corresponding `app/v1`,
  `app/v2`, or M04 `app/v3` source changes. Synchronize the matching asset and
  re-run every listed check in the next implementation batch.
- Keep M05 isolated. Do not copy it into an asset, add it to an acceptance
  baseline, or alter its snapshots while maintaining this Skill.

### Strict-conformance successor

This record preserves the 2026-08-13 source-to-asset synchronization evidence.
Its three static verifiers establish only that this repository's portable assets
match their source routes; they do not establish target-project conformance.
The successor [strict-conformance decision](./liquid-glass-interface-strict-conformance.en.md)
defines schema `2.0` strict kernels, six mode/framework manifests, frozen
integration hashes, structured E2E/visual evidence, full-tree contamination
scanning, and the mandatory human visual gate. The older portable bundles and
their verifiers remain publication references; they are not strict target
kernels or target-project evidence.
