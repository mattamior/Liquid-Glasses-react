# Apple Liquid Glass 官方设计逻辑

本文是本 Skill 的最高级设计判定基准。实现 Web 液态玻璃时，先满足苹果官方的材料语义，再选择具体技术。技术可因浏览器能力降级，但不得把偏离官方逻辑的效果继续称为 Apple-aligned Liquid Glass。

## 来源优先级

遇到冲突或不确定性时，按以下顺序判断，并在设计工作开始时重新检查当前版本：

1. [Apple Human Interface Guidelines：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)
2. [Apple Developer Documentation：Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass)
3. [Apple WWDC：Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)
4. 苹果其他官方平台文档与设计视频
5. 社区文章、实验和 Web 实现经验

社区资料只能补充实现方法，不能推翻苹果官方的使用场景、层级、材料变体或可读性原则。若用户明确要求偏离，先指出偏离，再把结果描述为自定义玻璃效果，而不是苹果官方材料的忠实复现。

## 功能层级与使用范围

Liquid Glass 属于浮在内容之上的功能层，优先用于导航、工具栏、标签栏、侧边栏、菜单、popover 和重要控件。不要把它普遍用于内容卡片、页面背景或装饰层，也不要堆叠 glass-on-glass。

材料应帮助人理解层级、状态和交互来源。若移除玻璃后，组件仍只是普通装饰容器，优先使用标准材质或普通半透明表面。使用系统原生组件时，应优先让系统提供 Liquid Glass；本 Skill 只处理 Web 近似实现。

## 光学模型：整个表面折射，边缘梯度更强

苹果将 Liquid Glass 的主要视觉特征描述为 lensing：材料实时弯曲、塑造和聚集背景光线，以显示自身的存在、形状和层级。

- 整个表面参与折射，不存在“折射”和“扭曲”完全分离的两个区域。
- 圆角边缘曲率与折射梯度更高，应出现更明显、沿表面法线变化的局部弯折、聚光和克制色散。
- 内部区域应保持低梯度和视觉稳定；允许轻微、连续的放大、位移、色调变化或散射，但不能出现无来源的波浪、拉伸或噪声。
- 前景标签、图标、焦点环和命中区域始终稳定，不参与背景折射。
- 普通模糊只能承担可读性与光散射，不能代替 lensing，也不能压过边缘折射成为主要观感。

因此，“内部仅折射而不扭曲”应解释为：内部仍有低梯度折射，但相邻采样点的位移变化很小，所以背景连续、稳定且可辨认；边缘因位移梯度增大而产生明显的形变。

## 四个独立维度

不要混淆以下维度：

| 维度 | 选项 | 含义 |
| --- | --- | --- |
| 苹果材料变体 | Regular / Clear | 由内容、可读性和使用场景决定 |
| Web 渲染能力 | Baseline / Enhanced | 是否启用场景副本与 SVG 位移 |
| 外观主题 | Light / Dark | 独立调校亮度、色散、阴影和对比度 |
| 交互状态 | Resting / Interactive | 静止、按压、选择、开合、形变等状态 |

Baseline/Enhanced 不是 Regular/Clear 的别名。一个 Regular 菜单既可以使用 Baseline 降级，也可以使用 Enhanced 折射。

## Regular 与 Clear

### Regular

Regular 是菜单、popover、侧边栏和包含较多文字组件的默认选择。它会根据背景调节模糊、亮度、色调、阴影和动态范围，以保证前景内容可读。其内部允许适度柔化，但仍需让环境颜色和结构可感知。

### Clear

Clear 更透明，优先保留照片、视频等丰富媒体背景，只在底部内容足够丰富、前景标签足够粗亮且允许加入暗化层时使用。Clear 缺少 Regular 的部分自适应行为；必要时加入局部 dimming，而不是增加不透明白色填充。

同一组件体系内不要随意混用 Regular 与 Clear。选择依据是语义和可读性，不是“哪种看起来更炫”。

## 尺寸、环境与内容适配

- 小型控件应轻、透明、安静；交互时才通过光线和形变增强反馈。
- 玻璃扩展为较大的菜单或侧边栏时，应表现为更厚的材料：阴影更深、lensing/refraction 更明显、光散射更柔和，但不能让内部背景失去连续性。
- 阴影、色调和动态范围应根据底部内容适配。覆盖文字时可以增强分离，覆盖均匀背景时应减弱。
- 小型控件可根据背景在亮暗外观间切换；大面积菜单不应频繁进行干扰性的整体亮暗翻转。
- 环境色可以克制地溢出到表面、高光和阴影，但不能形成固定蓝、青、紫闭环。
- tint 只用于强调主要操作或明确语义；避免所有元素着色，也避免以实色填充破坏透明材料感。

## 材料与运动必须统一

Liquid Glass 的视觉与运动是同一系统：

- 元素显现和消失应通过 lensing、光线、形态和厚度的连续变化表达，而不只是普通 fade。
- 按压、选择和触摸可让材料短暂变亮、形变或产生局部能量反馈；静止状态保持安静。
- 按钮展开为菜单时，应维持触发器、连接区域和内容之间的因果关系，像同一材料打开或合并，而不是两个独立面板交叉淡入。
- 形变过程中保持圆角、层级和光学完整性；减少动态效果时，保留即时、清晰的状态变化。

## 滚动内容、稳定状态与测试场景

Apple 的 Scroll Edge Effects 会在内容滚到玻璃下方时柔化、淡化或暗化内容，以维持导航和控件可读性。Web 实现应根据产品需要提供相同语义，而不是让复杂正文持续与控件竞争。

正式产品的稳定状态应尽量避免高对比文字与 Liquid Glass 产生干扰性交叉。盲测和视觉 QA 是例外：必须让文字、网格和色带穿过镜片边缘，以证明折射真实存在。不要把测试布景直接当成生产布局建议。

## 无障碍与性能

- Reduced Transparency：提高不透明度或磨砂程度，不能损坏层级与操作。
- Increased Contrast：增强前景、边界和状态区分。
- Reduced Motion：降低弹性、形变、视差和非必要光线运动。
- 性能不足时，先减少位移、滤镜面积和光学层数量，再退化到功能完整的标准材质。
- 多个相邻玻璃效果应共享或合并渲染资源；关闭或不可见的玻璃不得保留活跃滤镜。

## Apple-aligned 一票否决

出现以下任一情况，不得把结果称为 Apple-aligned Liquid Glass：

1. 用 blur、白色透明填充、噪声或固定彩圈冒充 lensing。
2. 整个内部持续波浪化、拉伸或扭曲，破坏背景连续性。
3. 边缘没有沿几何法线变化的局部折射。
4. 把 Baseline/Enhanced 当作 Regular/Clear。
5. 在内容层滥用玻璃或堆叠 glass-on-glass。
6. 为展示效果牺牲标签、焦点、对比度或命中区域。
7. 大小、背景、交互状态变化时，材料参数完全不适配。
8. 正式稳定布局故意制造持续的高对比内容交叉，却没有可读性处理。
9. 只依据社区实现或视觉流行趋势，而未检查苹果当前官方资料。
